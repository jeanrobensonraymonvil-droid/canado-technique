Paysage des menaces en Haïti (3 min) — Menaces les plus courantes: phishing/hameçonnage ciblant les employés, ransomware sur les partages réseau, accès non autorisé via Wi-Fi non sécurisé, attaques depuis internet.

Quiz — Chapitre 1

4 questions
Question 1 / 4
La triade CIA en sécurité informatique signifie...
CIA = Confidentiality + Integrity + Availability (Disponibilité). C'est le modèle fondamental de la sécurité informatique. Tout incident de sécurité affecte au moins un de ces trois piliers: une panne = Disponibilité, un vol de données = Confidentialité, une modification non autorisée = Intégrité.
Question 2 / 4
Une attaque ARP Spoofing vise à...
ARP Spoofing: l'attaquant envoie de fausses réponses ARP en disant "l'IP du routeur c'est mon adresse MAC". Les hôtes mettent à jour leur cache ARP et envoient leur trafic vers l'attaquant (qui peut le lire, le modifier et le retransmettre = MITM silencieux).
Question 3 / 4
Pourquoi Telnet est-il interdit sur les équipements réseau de production ?
Telnet = port 23, protocole texte clair. N'importe qui avec Wireshark sur le réseau peut capturer le login, le mot de passe et toutes les commandes d'administration. Utiliser exclusivement SSH (port 22, chiffré). Désactiver Telnet: line vty 0 4 → transport input ssh.
Question 4 / 4
La "défense en profondeur" en sécurité réseau signifie...
La défense en profondeur (defense in depth): si le pare-feu périmétrique est contourné (phishing), les ACL internes limitent la propagation. Si les ACL sont contournées, la segmentation VLAN isole l'impact. Si le VLAN est compromis, les droits AD limités protègent les données. Chaque couche ralentit l'attaquant.

🎬 Guide de production
1
ACL standard vs étendue (rappel + approfondissement) (4 min) — Standard: filtre uniquement sur l'IP source (numéros 1-99, 1300-1999). Étendue: filtre sur source + destination + protocole + port (100-199, 2000-2699).
2
Named ACL (4 min) — ip access-list extended NOM. Avantages: nom descriptif, réordonnable (permit/deny ajoutables à n'importe quelle position), plus lisible.
3
Cas d'usage sécurité (5 min) — Bloquer Telnet entrant, autoriser uniquement SSH, bloquer les RFC 1918 entrants sur l'interface WAN, implémenter des règles anti-spoofing.
4
Remarque finale des ACL (3 min) — Implicit deny all en fin de chaque ACL. Tester avec "show access-list" et les compteurs de hits.

2.1 ACL de sécurité essentielles sur routeur Cisco

Règle ACLCommandeJustification sécurité
Bloquer adresses RFC 1918 en entrée WANdeny ip 192.168.0.0 0.0.255.255 any / deny ip 10.0.0.0 0.255.255.255 any / deny ip 172.16.0.0 0.15.255.255 anyAnti-spoofing: les IPs privées ne doivent jamais venir d'internet
Bloquer adresses loopback/réservéesdeny ip 127.0.0.0 0.255.255.255 any / deny ip 0.0.0.0 0.255.255.255 anyLes paquets avec ces sources sur internet = falsifiés
Autoriser SSH uniquement (bloquer Telnet)permit tcp any host MGMT_IP eq 22 / deny tcp any host MGMT_IP eq 23SSH chiffré autorisé, Telnet interdit

Autoriser seulement le trafic établi en retourpermit tcp any any establishedAutorise uniquement les connexions initiées de l'intérieur
Deny all final (implicite)(implicite — pas besoin de la taper)Tout ce qui n'est pas explicitement autorisé est refusé

Quiz — Chapitre 2

4 questions
Question 1 / 4
Pourquoi bloquer les adresses RFC 1918 (192.168.x.x, 10.x.x.x, 172.16.x.x) sur l'interface WAN en entrée ?
Anti-spoofing: les adresses RFC 1918 sont non routables sur internet (privées). Si un paquet arrive sur l'interface WAN avec une source 192.168.x.x, c'est 100% falsifié. Bloquer ces paquets au niveau WAN évite les attaques de spoofing d'IP interne.
Question 2 / 4
Le "deny implicite" en fin de chaque ACL Cisco signifie...
Toutes les ACL Cisco ont un "deny any any" implicite à la fin. Conséquence: si on crée une ACL et qu'on l'applique à une interface SANS mettre de règles permit, TOUT le trafic est bloqué. Toujours vérifier qu'il y a suffisamment de règles permit avant d'appliquer une ACL sur une interface de production.
Question 3 / 4
La règle ACL "permit tcp any any established" autorise...
"established" correspond aux paquets TCP avec le bit ACK ou RST mis à 1. Cela autorise les paquets de retour pour les connexions initiées depuis le réseau interne. Les tentatives de connexion de l'extérieur vers l'intérieur (SYN sans ACK) sont bloquées.
Question 4 / 4
Une ACL Named (ip access-list extended NOM) est préférable à une ACL numérotée car...
Les ACL Named permettent de: nommer de façon descriptive (INBOUND-SECURITY plutôt que 101), insérer une règle à une position précise (sans réécrire toute l'ACL), supprimer une règle individuelle. Les ACL numérotées nécessitent de réécrire l'ACL entière pour tout modification.

Durée : 15 min

🎬 Guide de production
1
Types de pare-feu (4 min) — Pare-feu stateless (filtre par IP/port, sans état). Pare-feu stateful (suit l'état des connexions TCP). NGFW (Next Generation Firewall): inspection applicative, IPS intégré, anti-malware. Cisco ASA, Fortinet FortiGate, pfSense (open source).
2
DMZ — Zone démilitarisée (5 min) — Zone réseau entre internet et le LAN interne pour les serveurs publics (web, mail). Règles: internet peut accéder à la DMZ (ports limités), la DMZ ne peut pas initier de connexion vers le LAN interne, le LAN interne peut accéder à la DMZ.
3
Configuration pfSense (4 min) — pfSense = pare-feu open source basé sur FreeBSD. Installation sur PC dédié ou VM. Interface WAN, LAN, DMZ. Règles de filtrage. Idéal pour les PME haïtiennes avec budget limité.
4
NAT et PAT sur pare-feu (2 min) — Différence entre NAT sur routeur Cisco et NAT sur pare-feu. NAT statique pour les serveurs DMZ (1 IP publique → 1 serveur DMZ).

3.1 Architecture DMZ — Règles de trafic

Source → DestinationRègleJustification
Internet → DMZAutorisé sur ports spécifiques (80, 443, 25)Les services publics doivent être accessibles depuis internet
Internet → LAN InterneREFUSÉ par défautLe LAN interne ne doit jamais être directement accessible depuis internet
LAN Interne → DMZAutorisé (maintenance des serveurs DMZ)Les admins internes doivent pouvoir gérer les serveurs DMZ
LAN Interne → InternetAutorisé (avec inspection)Les utilisateurs internes accèdent à internet normalement
DMZ → LAN InterneREFUSÉ par défautSi un serveur DMZ est compromis, il ne doit pas pouvoir attaquer le LAN
DMZ → InternetAutorisé sur ports limités (DNS, NTP, mises à jour)Les serveurs DMZ ont besoin d'accès internet limité
🛡️ Règle d'or de la DMZUn serveur en DMZ peut être compromis — c'est pour ça qu'il est en DMZ et pas dans le LAN. La règle critique: la DMZ ne peut JAMAIS initier de connexion vers le LAN interne. Un serveur web piraté ne doit pas pouvoir accéder aux bases de données ou aux partages de fichiers internes.
📝

Quiz — Chapitre 3

4 questions
Question 1 / 4
Pourquoi placer les serveurs web et email en DMZ plutôt que directement dans le LAN ?
La DMZ est un périmètre d'isolation: les serveurs publics (web, mail) sont exposés à internet et donc à risque. En les plaçant en DMZ, une compromission ne donne pas accès au réseau interne (base de données, serveurs AD, partages fichiers).
Question 2 / 4
Un NGFW (Next Generation Firewall) peut faire ce qu'un pare-feu stateful classique ne peut pas, notamment...
Un pare-feu stateful classique voit TCP port 443 = HTTPS = OK. Un NGFW déchiffre le TLS (avec SSL inspection), inspecte le contenu à la recherche de malwares, identifie l'application réelle (YouTube, Dropbox, Teams), et applique des politiques par application.
Question 3 / 4
Pourquoi pfSense est-il recommandé pour les PME haïtiennes comme solution pare-feu ?
pfSense = FreeBSD + firewall open source gratuit. Il fonctionne sur un PC standard (même de récupération). Fonctionnalités: pare-feu stateful, VPN IPSec/OpenVPN, DHCP, DNS resolver, IDS/IPS Snort, rapport de trafic. Équivalent à des appliances commerciales à 2000-5000 USD pour le prix d'un PC.
Question 4 / 4
La règle "DMZ → LAN Interne : REFUSÉ" est critique car...
C'est LE principe fondamental de la DMZ: l'isolation. Un attaquant qui prend le contrôle d'un serveur web en DMZ ne doit pas pouvoir accéder aux serveurs AD, aux bases de données, aux partages de fichiers du LAN interne. La règle "DMZ no-access to LAN" garantit cette isolation.

🎬 Guide de production
1
IDS vs IPS (4 min) — IDS (Intrusion Detection System): détecte et alerte. IPS (Intrusion Prevention System): détecte et bloque automatiquement. Snort (open source, dans pfSense/Suricata). HIDS (basé sur l'hôte) vs NIDS (réseau).
2
802.1X — Authentification réseau (4 min) — Contrôle l'accès au réseau: avant d'obtenir une IP, l'équipement doit s'authentifier (via AD, certificat). Empêche les connexions non autorisées au réseau (visiteurs, équipements inconnus). RADIUS server.
3
Audit de sécurité réseau (4 min) — Nmap pour la découverte, Nessus/OpenVAS pour les vulnérabilités, revue des ACL et règles pare-feu, test d'intrusion (pentest) avec autorisation.
4
Checklist de durcissement Cisco (3 min) — Désactiver CDP sur les interfaces publiques, désactiver les services inutiles (ip http server, telnet), activer SSH v2, NTP sécurisé, SNMP v3 uniquement.

Quiz — Chapitre 4

4 questions
Question 1 / 4
La différence principale entre un IDS et un IPS est...
IDS = alarme qui sonne mais n'empêche pas le voleur d'entrer. IPS = alarme + porte qui se verrouille automatiquement. L'IPS doit être placé en ligne (inline) dans le flux réseau pour pouvoir bloquer. L'IDS est placé en parallèle (SPAN port) et ne peut qu'alerter.
Question 2 / 4
Le protocole 802.1X contrôle...
802.1X (NAC — Network Access Control): quand un équipement se connecte à un port switch, le switch demande une authentification via RADIUS (AD). Si l'authentification échoue, le port reste en VLAN de quarantaine ou est bloqué. Empêche les équipements personnels non autorisés de rejoindre le réseau d'entreprise.
Question 3 / 4
Pourquoi désactiver CDP (Cisco Discovery Protocol) sur les interfaces connectées à internet ou aux visiteurs ?
CDP diffuse régulièrement des trames avec: le hostname du switch/routeur, le modèle exact (Catalyst 2960, ISR 4321), la version IOS, les adresses IP de toutes les interfaces. Un attaquant connecté (ou un visiteur malveillant) obtient gratuitement une cartographie de l'infrastructure.
Question 4 / 4
Nessus et OpenVAS sont des outils utilisés pour...
Nessus (Tenable) et OpenVAS (open source) scannent une infrastructure et identifient les vulnérabilités connues (CVE): OS non patchés, services vulnérables, configurations faibles. Ils produisent des rapports priorisés. À utiliser régulièrement en audit de sécurité interne (avec autorisation).

Devoir TRI-26 — Politique de sécurité réseau — Organisation haïtienne

📋 Instructions
  1. Rédige le contexte de menaces: les 5 principales menaces auxquelles cette institution est exposée, avec leur probabilité et leur impact potentiel.

Quiz — Chapitre 1

4 questions
Question 1 / 4
Quelle technologie WAN offre les meilleures performances (débit + latence garantis) pour interconnecter les sièges sociaux de deux banques haïtiennes ?
MPLS (Multiprotocol Label Switching) est un réseau privé géré par l'opérateur avec des garanties de débit, latence et disponibilité (SLA). Idéal pour les transactions bancaires critiques qui ne tolèrent pas la variabilité d'internet public. Plus coûteux que les alternatives.
Question 2 / 4
Pour un bureau secondaire dans une ville de province haïtienne, quelle est la solution WAN la plus pragmatique ?
La 4G LTE est disponible dans la quasi-totalité des zones urbaines haïtiennes. Un routeur avec deux SIM (Natcom + Digicel) donne de la redondance: si l'un des opérateurs a une panne, l'autre prend le relais. C'est la solution la plus pragmatique et économique pour les bureaux de province.
Question 3 / 4
Combien de bande passante WAN minimum faut-il prévoir pour 20 utilisateurs faisant essentiellement de la navigation web et des emails ?
Estimation: 20 users × 1 Mbps (navigation + email) = 20 Mbps. Avec de la marge (pics d'utilisation, mises à jour Windows, cloud apps): viser 20-30 Mbps. Pour ajouter la VoIP: +20 appels simultanés × 100 Kbps = +2 Mbps. Total recommandé: 25-30 Mbps.
Question 4 / 4
Starlink est particulièrement utile en Haïti pour...
Starlink (satellite LEO) est révolutionnaire pour les zones sans fibre ni 4G, et comme backup lors des ouragans quand les infrastructures terrestres sont détruites. Les 25-60 ms de latence sont acceptables pour la plupart des usages sauf certains jeux en ligne.

🎬 Guide de production
1
Pourquoi le VPN ? (4 min) — Transporter des données privées sur un réseau public (internet). Chiffrement du tunnel. Types: Site-to-Site (LAN-to-LAN), Remote Access (client VPN), SSL/TLS VPN.
2
IPSec — Le protocole VPN de référence (5 min) — Deux modes: Transport (chiffre les données) et Tunnel (chiffre tout le paquet IP). Protocoles: AH (Authentication Header), ESP (Encapsulating Security Payload). Phases IKE.
3
SSL/TLS VPN (3 min) — Accès via navigateur web ou client léger. Pas de configuration sur le poste client. Idéal pour le télétravail. Exemples: Cisco AnyConnect, OpenVPN, WireGuard.
4
WireGuard — Le VPN moderne (4 min) — Protocole moderne, rapide, 4000 lignes de code vs 600 000 pour OpenVPN. Basé sur ChaCha20/Poly1305. De plus en plus populaire pour le télétravail.

Quiz — Chapitre 2

4 questions
Question 1 / 4
Un VPN site-à-site (LAN-to-LAN) connecte...
VPN site-à-site: les routeurs/firewalls des deux sites établissent un tunnel IPSec permanent. Les hôtes des deux sites communiquent normalement — ils ne savent pas qu'ils traversent un tunnel VPN. Exemple: siège à Port-au-Prince ↔ bureau au Cap-Haïtien via internet chiffré.
Question 2 / 4
Pourquoi PPTP est-il déconseillé aujourd'hui ?
PPTP utilise MS-CHAPv2 pour l'authentification et MPPE pour le chiffrement — des algorithmes vulnérables. Des attaques pratiques permettent de déchiffrer le trafic PPTP en quelques heures. Utiliser L2TP/IPSec, IKEv2, OpenVPN, ou WireGuard à la place.
Question 3 / 4
WireGuard se distingue d'OpenVPN principalement par...
WireGuard: ~4 000 lignes de code (surface d'attaque minimale, plus facile à auditer), ChaCha20/Poly1305/Curve25519 (cryptographie moderne), temps de handshake ultra-rapide, excellentes performances. De plus en plus adopté comme standard pour le VPN.
Question 4 / 4
Dans un VPN IPSec en mode Tunnel, qu'est-ce qui est chiffré ?
Mode Tunnel: tout le paquet IP original (en-tête + données) est chiffré et encapsulé dans un nouveau paquet IP avec les adresses des passerelles VPN. C'est le mode utilisé pour les VPN site-à-site. Mode Transport: seules les données sont chiffrées, l'en-tête IP original reste visible.

🎬 Guide de production
1
Phases IKE (3 min) — Phase 1 (IKE SA): authentification des deux routeurs et établissement d'un canal sécurisé. Phase 2 (IPSec SA): négociation des paramètres de chiffrement du tunnel de données.
2
Configuration crypto map (6 min) — 1) ACL intéressant (définir quel trafic sera dans le tunnel). 2) ISAKMP policy (paramètres Phase 1). 3) IPSec transform-set (paramètres Phase 2). 4) Crypto map (assembler tout). 5) Appliquer sur l'interface WAN.
3
Vérification (4 min) — show crypto isakmp sa (Phase 1 up?), show crypto ipsec sa (Phase 2 + compteurs de paquets chiffrés).
4
Dépannage IPSec (3 min) — debug crypto isakmp, debug crypto ipsec. Problèmes courants: ACL asymétriques, pre-shared key incorrecte, mismatche de transform-set.

Quiz — Chapitre 3

4 questions
Question 1 / 4
La Phase 1 IKE (ISAKMP SA) dans un VPN IPSec sert à...
Phase 1 IKE: les deux passerelles VPN s'authentifient mutuellement (via PSK ou certificats) et établissent un canal sécurisé. Ce canal sert uniquement à négocier les paramètres de la Phase 2. show crypto isakmp sa doit afficher "QM_IDLE" pour une Phase 1 réussie.
Question 2 / 4
Dans la configuration IPSec Cisco, à quoi sert l'ACL "intéressant" ?
L'ACL "intéressant" définit la politique: quand un paquet correspond à cette ACL (source = LAN local, destination = LAN distant), le routeur l'envoie dans le tunnel IPSec chiffré. Le reste du trafic est traité normalement (routing internet).
Question 3 / 4
Si "show crypto isakmp sa" affiche "MM_NO_STATE", cela indique...
"MM_NO_STATE" signifie que la Phase 1 n'a pas pu aboutir. Causes fréquentes: PSK différente entre les deux sites, politiques ISAKMP incompatibles (encryption/hash/group différents), ou connectivité IP manquante entre les interfaces WAN.
Question 4 / 4
Pourquoi les deux routeurs VPN doivent-ils avoir des ACL "intéressants" SYMÉTRIQUES ?
Un tunnel IPSec doit pouvoir initier le chiffrement dans les deux sens. L'ACL du routeur A dit "chiffrer les paquets de mon LAN vers le LAN distant". L'ACL du routeur B dit l'inverse. Si les ACL ne sont pas symétriques, le trafic ne passera que dans un sens.

🎬 Guide de production
1
SD-WAN — Software-Defined WAN (5 min) — Gérer plusieurs liens WAN (fibre + 4G + MPLS) depuis un contrôleur centralisé. Routage intelligent selon l'application. Cisco Viptela, Meraki, Fortinet SD-WAN.
2
DMVPN — Dynamic Multipoint VPN (4 min) — VPN hub-and-spoke: un site central (hub) + N sites distants (spokes). Les spokes peuvent communiquer directement entre eux via NHRP. Scalable: ajouter un site = 5 minutes.
3
Accès cloud et Direct Connect (3 min) — AWS Direct Connect, Azure ExpressRoute: connexion privée dédiée vers le cloud (pas via internet). Idéal pour les applications critiques en cloud.
4
Scénario haïtien — Multi-sites avec cloud (3 min) — Architectures hybrides: siège (fibre + MPLS) → branches (4G + VPN) → cloud AWS (applications hébergées). De plus en plus commun pour les banques et ONG internationales en Haïti.

Quiz — Chapitre 4

4 questions
Question 1 / 4
SD-WAN apporte comme principal avantage par rapport à une architecture VPN traditionnelle...
SD-WAN: un contrôleur central gère tous les liens WAN (fibre + 4G + MPLS) et route le trafic de façon intelligente selon l'application (Teams via fibre, Netflix bloqué, sauvegardes via 4G pendant les heures creuses). Révolutionnaire pour les entreprises multi-sites.
Question 2 / 4
DMVPN (Dynamic Multipoint VPN) est avantageux pour une organisation avec 20 agences car...
DMVPN hub-and-spoke: configurer le hub une fois. Chaque nouveau spoke (agence) s'ajoute en quelques minutes. Les spokes peuvent communiquer directement entre eux via NHRP (Next Hop Resolution Protocol) sans surcharger le hub central.
Question 3 / 4
AWS Direct Connect et Azure ExpressRoute sont utilisés pour...
Direct Connect (AWS) et ExpressRoute (Azure) fournissent une connexion physique dédiée entre le datacenter de l'entreprise et le cloud. Pas de transit par internet public = latence prévisible, débit garanti, sécurité renforcée. Utilisé pour les applications critiques migrées vers le cloud.
Question 4 / 4
Pour une banque haïtienne avec 15 agences dans tout le pays, quelle architecture WAN recommanderais-tu ?
Architecture hybride recommandée: MPLS garanti pour les agences à fort volume (Port-au-Prince, Cap-Haïtien, Gonaïves) où les transactions sont critiques. 4G LTE + VPN pour les agences de province où le MPLS n'est pas disponible. SD-WAN pour gérer l'ensemble depuis un tableau de bord centralisé.

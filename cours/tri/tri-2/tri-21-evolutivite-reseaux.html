Énoncé de la compétence

Implanter un réseau commuté.

Présentation du module

Ce module porte sur la commutation LAN : à partir d'une étude de cas, l'étudiant implante un réseau commuté complet — configuration des commutateurs, réseaux locaux virtuels (VLAN), protocole VTP, spanning tree (STP/RSTP), routage inter-VLAN et intégration d'un réseau sans fil. Il prolonge TRI-19 dans le parcours menant à la certification CCNA.

Éléments de la compétence

  1. Analyser le scénario d'implantation.
  2. Établir un plan d'adressage IP sans classe.
  3. Configurer un commutateur.
  4. Configurer des réseaux locaux virtuels (VLAN).
  5. Configurer le protocole VTP.
  6. Configurer les protocoles STP et RSTP.
  7. Configurer le routage entre les VLAN.
  8. Intégrer un réseau sans fil dans un réseau commuté (WiFi).
  9. Consigner l'information sur l'installation.

Critères généraux de performance

  • Respect des normes de sécurité.
  • Utilisation appropriée de l'outillage, de l'équipement, du matériel et des logiciels.
  • Respect des normes d'installation et de câblage.
  • Choix approprié de la documentation technique.
  • Interprétation juste de la terminologie française et anglaise.
  • Utilisation correcte des logiciels de simulation et de configuration.
  • Utilisation des commandes appropriées ; rapidité d'exécution.

Contexte de réalisation

À partir deÉtudes de cas représentatives des entreprises du pays · normes de sécurité · accès Internet · ordinateurs et logiciels de simulation · 1 aiguilleur, 2 commutateurs et de l'équipement réseau sans fil.

🔑 Termes clés
Couche d'accès — l'étage qui connecte les utilisateurs : ports, PoE, sécurité de port.
Couche de distribution — l'étage intermédiaire : routage inter-VLAN, ACL, agrégation des accès.
Couche cœur (core) — l'autoroute du réseau : commutation très rapide, redondance, aucune manipulation de paquets.
Collapsed core — architecture à deux niveaux où distribution et cœur fusionnent — typique des PME.
Redondance — liens et équipements doublés pour éliminer les points de défaillance uniques.
Évolutivité (scalability) — capacité du réseau à grandir sans être reconstruit — l'objectif central de ce module.

1.1 Modèle hiérarchique à 3 couches

CoucheRôleÉquipements typiquesFonctions clés
Accès (Access)Connecter les hôtes finauxCatalyst 2960, 2960X, 9200PoE, Port Security, VLANs, STP PortFast, DHCP Relay
DistributionAgrégation + politiquesCatalyst 3850, 3750, 9300Routage inter-VLAN (L3), ACL, QoS, HSRP/VRRP, Summarization
Cœur (Core)Backbone haute vitesseCatalyst 9500, Nexus 7K, Routeurs ISRRedondance maximale, haut débit (10/40/100G), pas de politiques complexes
📐 Règle d'or — Cisco 3-Tier Ne jamais mettre de logique complexe (ACL, QoS lourde) au niveau Core — le Cœur doit transmettre les paquets le plus rapidement possible. Les politiques et le filtrage sont appliqués à la couche Distribution. Les connexions hôtes sont gérées à la couche Accès.

1.2 Collapsed Core — Architecture à 2 couches

🏫 Architecture pour Canado Technique Pour une école de taille moyenne, le modèle Collapsed Core est idéal : Distribution et Core fusionnent sur un switch L3 central. Les switchs d'accès se connectent en étoile vers ce switch central.

Exemple Canado Technique :
• SW-Core (Catalyst 3750) — Collapsed Core + Distribution : routage inter-VLAN, SVI par VLAN
• SW-Salle-A, SW-Salle-B (Catalyst 2960) — Accès : ports étudiant, prof, labo
• R-Internet (ISR 4321) — Connexion ISP, NAT, DHCP serveur central
📌 Bon à savoir
  • Règle d'or : l'accès connecte, la distribution décide (routage, ACL), le cœur transporte — ne mélange pas les rôles.
  • En PME, le collapsed core à deux niveaux suffit : moins cher, plus simple, parfaitement évolutif.
  • La redondance se planifie à CHAQUE niveau : double uplink, double alimentation, double équipement de cœur.
  • Pense « modules » : chaque bloc (accès+distribution) peut être dupliqué pour faire grandir le réseau.

2.1 Switch Layer 3 — Configuration ip routing

Cisco IOS — Switch L3 avec SVIs
! === SWITCH L3 — ip routing activé (alternative au Router-on-a-Stick) ===
SW-Core(config)# ip routing                     ← activer le routage L3 sur le switch

! Créer les SVIs (interfaces virtuelles VLAN) qui servent de passerelles
SW-Core(config)# interface vlan 10
SW-Core(config-if)# ip address 192.168.10.1 255.255.255.0
SW-Core(config-if)# no shutdown
SW-Core(config-if)# exit

SW-Core(config)# interface vlan 20
SW-Core(config-if)# ip address 192.168.20.1 255.255.255.0
SW-Core(config-if)# no shutdown
SW-Core(config-if)# exit

! Route statique par défaut vers le routeur Internet
SW-Core(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1

! Vérification
SW-Core# show ip route          ← doit montrer C 192.168.10.0/24 et C 192.168.20.0/24
SW-Core# show ip interface brief ← SVIs en état up/up

Cisco IOS — Récupération err-disabled
! Récupération manuelle d'un port err-disabled
SW(config)# interface GigabitEthernet0/1
SW(config-if)# shutdown
SW(config-if)# no shutdown          ← remet le port en service

! Récupération automatique (évite intervention manuelle)
SW(config)# errdisable recovery cause psecure-violation
SW(config)# errdisable recovery interval 300    ← récupère après 5 minutes

! Vérification
SW# show errdisable recovery
SW# show port-security interface GigabitEthernet0/1
📌 Bon à savoir
  • Un commutateur L3 route à la vitesse du matériel (CEF) — bien plus vite qu'un routeur d'entrée de gamme.
  • Le stacking transforme 2 à 8 commutateurs en un seul : une seule IP de gestion, une seule configuration.
  • Critères d'achat : densité de ports, PoE, débit fond de panier, capacité L3 — dans cet ordre pour un réseau d'école.
  • Les uplinks doivent être plus rapides que les ports d'accès : accès 1 Gb/s → uplink 10 Gb/s.

🔑 Termes clés
DTP — Dynamic Trunking Protocol : négociation automatique des trunks entre commutateurs Cisco.
dynamic auto / desirable — auto attend une demande, desirable la provoque — deux auto ensemble ne forment JAMAIS de trunk.
switchport nonegotiate — désactive DTP : le mode du port devient fixe — recommandé en production.
VLAN hopping — attaque où un poste se fait passer pour un commutateur (faux DTP) pour accéder à tous les VLANs.
Double tagging — attaque utilisant deux étiquettes 802.1Q pour sauter dans un autre VLAN via le VLAN natif.
VLAN voix — VLAN dédié à la téléphonie IP : switchport voice vlan 150.

3.1 Matrice de négociation DTP

Port local \ Port distantDynamic AutoDynamic DesirableTrunkAccess
Dynamic AutoAccessTrunk ✅Trunk ✅Access
Dynamic DesirableTrunk ✅Trunk ✅Trunk ✅Access
TrunkTrunk ✅Trunk ✅Trunk ✅Désaccord ⚠️
AccessAccessAccessDésaccord ⚠️Access
⚠️ Sécurité DTP — Toujours désactiver en production DTP permet une attaque "Switch Spoofing" : un attaquant envoie des paquets DTP pour négocier un trunk et accéder à tous les VLANs.
Bonne pratique : switchport nonegotiate + forcer le mode statiquement.
SW(config-if)# switchport mode trunk
SW(config-if)# switchport nonegotiate

3.2 Voice VLAN — Port à double VLAN

Cisco IOS — Voice VLAN (téléphone IP)
! Port connecté à un téléphone IP Cisco (qui a un port PC intégré)
! VLAN 10 = données PC derrière le téléphone
! VLAN 50 = voix (priorité QoS automatique : DSCP EF)
SW(config)# interface GigabitEthernet0/3
SW(config-if)# switchport mode access
SW(config-if)# switchport access vlan 10         ← données du PC
SW(config-if)# switchport voice vlan 50           ← voix du téléphone IP
SW(config-if)# mls qos trust cos                 ← faire confiance au marquage QoS du téléphone
SW(config-if)# spanning-tree portfast             ← port hôte, pas de wait STP
SW(config-if)# exit

! Le téléphone IP apprend le VLAN Voice via CDP automatiquement
SW# show interfaces GigabitEthernet0/3 switchport
  Administrative Mode: static access
  Access Mode VLAN: 10 (Data)
  Voice VLAN: 50 (Voix)
📌 Bon à savoir
  • Deux ports en dynamic auto ne formeront JAMAIS un trunk — piège d'examen classique.
  • En production : mode access ou trunk FIXE + switchport nonegotiate. On ne laisse pas DTP décider.
  • Contre le double tagging : le VLAN natif ne doit JAMAIS être un VLAN utilisateur — dédie-lui un VLAN inutilisé.
  • Désactive les ports inutilisés et place-les dans un VLAN « parking » : porte fermée, clé retirée.

🔑 Termes clés
SVI — interface VLAN logique d'un commutateur L3 : la passerelle des machines du VLAN.
ip routing — la commande qui transforme le commutateur L3 en routeur.
Port routé — port physique sorti du mode commutation avec no switchport, qui porte une adresse IP.

4.2 Dépannage inter-VLAN — Checklist

Cisco IOS — Dépannage inter-VLAN systématique
! ÉTAPE 1 : ip routing est-il activé ?
SW-Core# show running-config | include ip routing
ip routing                     ← doit être présent. Sinon : SW-Core(config)# ip routing

! ÉTAPE 2 : Les SVIs existent-elles et sont-elles up/up ?
SW-Core# show ip interface brief
Vlan10      192.168.10.1    YES manual  up     up      ← OK
Vlan20      192.168.20.1    YES manual  up     up      ← OK
Vlan20      unassigned      YES unset   down   down    ← problème : VLAN 20 pas créé !

! ÉTAPE 3 : Si SVI est down — le VLAN existe-t-il ?
SW-Core# show vlan brief              ← VLAN doit être présent et "active"
! Si absent : SW-Core(config)# vlan 20

! ÉTAPE 4 : Les ports sont-ils dans le bon VLAN ?
SW-Core# show interfaces GigabitEthernet0/1 switchport

! ÉTAPE 5 : Test de connectivité inter-VLAN
SW-Core# ping 192.168.20.10 source vlan 10    ← ping inter-VLAN depuis switch
📌 Bon à savoir
  • SVI = passerelle d'un VLAN ; port routé = lien point à point vers un autre routeur. Deux outils différents.
  • N'oublie pas ip routing : sans elle, ton commutateur L3 reste un simple commutateur.
  • SVI bat router-on-a-stick dès que le trafic inter-VLAN est important : pas de goulot sur un seul câble.
  • Une SVI ne monte que si le VLAN existe ET qu'au moins un port actif lui appartient.

🔑 Termes clés
RSTP (802.1w) — Spanning Tree rapide : convergence en quelques secondes au lieu de 30 à 50.
États RSTP — trois états seulement : discarding, learning, forwarding.
Rôles de port — root (vers la racine), designated (vers le segment), alternate (secours), backup.
PVST+ — une instance Spanning Tree par VLAN — permet d'équilibrer la charge entre liens.
Edge port — équivalent RSTP de PortFast : passe directement en forwarding, pour les postes uniquement.

5.1 Comparaison STP 802.1D vs RSTP 802.1w

CaractéristiqueSTP 802.1D (classique)RSTP 802.1w
États des portsBlocking, Listening, Learning, Forwarding, Disabled (5)Discarding, Learning, Forwarding (3)
Convergence30–50 secondes (Listening 15s + Learning 15s)Sub-seconde (1–6 secondes)
Types de portsRoot, Designated, Non-designated (Blocked)Root, Designated, Alternate, Backup
MécanismeTimers basésNégociation P/A (Proposal/Agreement)
Cisco PVST+PVST+ (par VLAN)Rapid PVST+ (par VLAN, rapide)

5.2 Load balancing STP avec PVST+

Cisco IOS — STP Load Balancing
! Topologie : SW-Core et SW-Dist reliés par 2 trunks redondants
! Objectif : VLAN 10 trafic passe par Trunk1, VLAN 20 par Trunk2

! === SW-Core : Root Bridge pour VLAN 10, secondaire pour VLAN 20 ===
SW-Core(config)# spanning-tree vlan 10 root primary       ← priorité 24576
SW-Core(config)# spanning-tree vlan 20 root secondary     ← priorité 28672

! === SW-Dist : Root Bridge pour VLAN 20, secondaire pour VLAN 10 ===
SW-Dist(config)# spanning-tree vlan 20 root primary
SW-Dist(config)# spanning-tree vlan 10 root secondary

! Activer Rapid PVST+ (recommandé sur tous les switches)
SW(config)# spanning-tree mode rapid-pvst

! Root Guard — empêche un switch non autorisé de devenir Root Bridge
SW-Core(config)# interface GigabitEthernet0/1
SW-Core(config-if)# spanning-tree guard root

! Vérification
SW# show spanning-tree vlan 10
SW# show spanning-tree vlan 20
📌 Bon à savoir
  • RSTP converge en 2-3 secondes contre 30-50 pour STP : active toujours rapid-pvst sur du matériel moderne.
  • spanning-tree mode rapid-pvst + spanning-tree portfast (edge) sur les ports d'accès : le combo standard.
  • PVST+ permet l'équilibrage : S1 root des VLANs impairs, S2 root des VLANs pairs — les deux uplinks travaillent.
  • Un port alternate est ta roue de secours : il passe en forwarding quasi instantanément si le chemin actif tombe.

6.2 Configuration EtherChannel

Cisco IOS — EtherChannel LACP, PAgP, Mode On
! === LACP — 802.3ad (recommandé, multi-vendeur) ===
SW-Core(config)# interface range GigabitEthernet0/1 - 2
SW-Core(config-if-range)# channel-group 1 mode active      ← Active initie LACP
SW-Core(config-if-range)# exit

! Configuration du port-channel (interface logique)
SW-Core(config)# interface port-channel 1
SW-Core(config-if)# switchport mode trunk
SW-Core(config-if)# switchport trunk native vlan 99
SW-Core(config-if)# switchport trunk allowed vlan 10,20,30
SW-Core(config-if)# exit

🔑 Termes clés

📌 Bon à savoir
  • SLAAC = zéro serveur : le routeur annonce le préfixe, l'hôte fabrique le reste. Magique mais sans DNS → d'où le stateless.
  • M=0,O=0 : SLAAC pur · M=0,O=1 : SLAAC + DNS via DHCPv6 stateless · M=1 : tout via DHCPv6 stateful.
  • La passerelle IPv6 d'un hôte est la link-local fe80:: du routeur — pas son adresse globale. Surprise garantie au TP !
  • Sans ipv6 unicast-routing, pas de RA, donc pas de SLAAC : c'est la première commande à vérifier en dépannage IPv6.

9.1 DHCP Snooping — Protection contre les rogue servers

Cisco IOS — DHCP Snooping + DAI
! === DHCP SNOOPING ===
SW(config)# ip dhcp snooping                       ← activer globalement
SW(config)# ip dhcp snooping vlan 10,20,30          ← activer sur les VLANs
SW(config)# no ip dhcp snooping information option  ← désactiver option 82 (évite problèmes)

! Port Trusted = uplink vers routeur/serveur DHCP réel
SW(config)# interface GigabitEthernet1/1          ← port trunk vers SW-Core
SW(config-if)# ip dhcp snooping trust
SW(config-if)# exit
! Tous les autres ports (hôtes) = Untrusted par défaut
! → les DHCP Offers venant de ports Untrusted sont bloqués !

! === DAI — Dynamic ARP Inspection ===
SW(config)# ip arp inspection vlan 10,20,30
! Port trusted (idem que DHCP snooping)
SW(config)# interface GigabitEthernet1/1
SW(config-if)# ip arp inspection trust
SW(config-if)# exit

! === STORM CONTROL ===
SW(config)# interface GigabitEthernet0/1
SW(config-if)# storm-control broadcast level 20      ← bloque si broadcast > 20%
SW(config-if)# storm-control action shutdown
SW(config-if)# exit

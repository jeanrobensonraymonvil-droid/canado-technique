1.1 Modèle hiérarchique à 3 couches

CoucheRôleÉquipements typiquesFonctions clés
Accès (Access)Connecter les hôtes finauxCatalyst 2960, 2960X, 9200PoE, Port Security, VLANs, STP PortFast, DHCP Relay
DistributionAgrégation + politiquesCatalyst 3850, 3750, 9300Routage inter-VLAN (L3), ACL, QoS, HSRP/VRRP, Summarization
Cœur (Core)Backbone haute vitesseCatalyst 9500, Nexus 7K, Routeurs ISRRedondance maximale, haut débit (10/40/100G), pas de politiques complexes
📐 Règle d'or — Cisco 3-Tier Ne jamais mettre de logique complexe (ACL, QoS lourde) au niveau Core — le Cœur doit transmettre les paquets le plus rapidement possible. Les politiques et le filtrage sont appliqués à la couche Distribution. Les connexions hôtes sont gérées à la couche Accès.

1.2 Collapsed Core — Architecture à 2 couches

🏫 Architecture pour Canado Technique Pour une école de taille moyenne, le modèle Collapsed Core est idéal : Distribution et Core fusionnent sur un switch L3 central. Les switchs d'accès se connectent en étoile vers ce switch central.

Exemple Canado Technique :
• SW-Core (Catalyst 3750) — Collapsed Core + Distribution : routage inter-VLAN, SVI par VLAN
• SW-Salle-A, SW-Salle-B (Catalyst 2960) — Accès : ports étudiant, prof, labo
• R-Internet (ISR 4321) — Connexion ISP, NAT, DHCP serveur central

2.1 Switch Layer 3 — Configuration ip routing

Cisco IOS — Switch L3 avec SVIs

SW-Core(config-if)# no shutdown

! Vérification
SW-Core# show ip route          ← doit montrer C 192.168.10.0/24 et C 192.168.20.0/24
SW-Core# show ip interface brief ← SVIs en état up/up

Cisco IOS — Récupération err-disabled
! Récupération manuelle d'un port err-disabled
SW(config)# interface GigabitEthernet0/1
SW(config-if)# shutdown

SW(config)# errdisable recovery cause psecure-violation
SW(config)# errdisable recovery interval 300    ← récupère après 5 minutes

3.1 Matrice de négociation DTP

Port local \ Port distantDynamic AutoDynamic DesirableTrunkAccess
Dynamic AutoAccessTrunk ✅Trunk ✅Access

⚠️ Sécurité DTP — Toujours désactiver en production DTP permet une attaque "Switch Spoofing" : un attaquant envoie des paquets DTP pour négocier un trunk et accéder à tous les VLANs.
Bonne pratique : switchport nonegotiate + forcer le mode statiquement.
SW(config-if)# switchport mode trunk
SW(config-if)# switchport nonegotiate

3.2 Voice VLAN — Port à double VLAN

Cisco IOS — Voice VLAN (téléphone IP)
! Port connecté à un téléphone IP Cisco (qui a un port PC intégré)
! VLAN 10 = données PC derrière le téléphone
! VLAN 50 = voix (priorité QoS automatique : DSCP EF)
SW(config)# interface GigabitEthernet0/3
SW(config-if)# switchport mode access
SW(config-if)# switchport access vlan 10         ← données du PC
SW(config-if)# switchport voice vlan 50           ← voix du téléphone IP
SW(config-if)# mls qos trust cos                 ← faire confiance au marquage QoS du téléphone
SW(config-if)# spanning-tree portfast             ← port hôte, pas de wait STP
SW(config-if)# exit

! Le téléphone IP apprend le VLAN Voice via CDP automatiquement
SW# show interfaces GigabitEthernet0/3 switchport
  Administrative Mode: static access
  Access Mode VLAN: 10 (Data)
  Voice VLAN: 50 (Voix)

5.2 Load balancing STP avec PVST+

Cisco IOS — STP Load Balancing
! Topologie : SW-Core et SW-Dist reliés par 2 trunks redondants
! Objectif : VLAN 10 trafic passe par Trunk1, VLAN 20 par Trunk2

! === SW-Core : Root Bridge pour VLAN 10, secondaire pour VLAN 20 ===
SW-Core(config)# spanning-tree vlan 10 root primary       ← priorité 24576
SW-Core(config)# spanning-tree vlan 20 root secondary     ← priorité 28672

! === SW-Dist : Root Bridge pour VLAN 20, secondaire pour VLAN 10 ===
SW-Dist(config)# spanning-tree vlan 20 root primary
SW-Dist(config)# spanning-tree vlan 10 root secondary

! Activer Rapid PVST+ (recommandé sur tous les switches)
SW(config)# spanning-tree mode rapid-pvst

! Root Guard — empêche un switch non autorisé de devenir Root Bridge
SW-Core(config)# interface GigabitEthernet0/1
SW-Core(config-if)# spanning-tree guard root

! Vérification
SW# show spanning-tree vlan 10
SW# show spanning-tree vlan 20

6.2 Configuration EtherChannel

SLAAC (6 min) — Stateless Address AutoConfiguration. Le client IPv6 utilise les Router Advertisements (RA) du routeur pour construire sa propre adresse GUA (préfixe /64 + EUI-64 ou random). Drapeaux M et O.

9.1 DHCP Snooping — Protection contre les rogue servers

Cisco IOS — DHCP Snooping + DAI
! === DHCP SNOOPING ===
SW(config)# ip dhcp snooping                       ← activer globalement
SW(config)# ip dhcp snooping vlan 10,20,30          ← activer sur les VLANs
SW(config)# no ip dhcp snooping information option  ← désactiver option 82 (évite problèmes)

! Port Trusted = uplink vers routeur/serveur DHCP réel
SW(config)# interface GigabitEthernet1/1          ← port trunk vers SW-Core
SW(config-if)# ip dhcp snooping trust
SW(config-if)# exit
! Tous les autres ports (hôtes) = Untrusted par défaut
! → les DHCP Offers venant de ports Untrusted sont bloqués !

! === DAI — Dynamic ARP Inspection ===
SW(config)# ip arp inspection vlan 10,20,30
! Port trusted (idem que DHCP snooping)
SW(config)# interface GigabitEthernet1/1
SW(config-if)# ip arp inspection trust
SW(config-if)# exit

! === STORM CONTROL ===
SW(config)# interface GigabitEthernet0/1
SW(config-if)# storm-control broadcast level 20      ← bloque si broadcast > 20%
SW(config-if)# storm-control action shutdown
SW(config-if)# exit

! Vérification
SW# show ip dhcp snooping binding             ← table de liaison DHCP
SW# show ip arp inspection vlan 10            ← statistiques DAI

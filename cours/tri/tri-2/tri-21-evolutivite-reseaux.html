🎬 Guide de production
1
Le modèle en 3 couches (5 min) — Access layer (switches d'accès connectant les postes), Distribution layer (switches de distribution, routage inter-VLAN, politiques), Core layer (backbone haute vitesse, pas de filtrage).
2

4
Exemple haïtien (3 min) — Architecture pour une banque avec 3 étages à Port-au-Prince. 1 switch de core, 3 switches de distribution (1 par étage), N switches d'accès.

Cette architecture est moins coûteuse et suffisante pour la plupart des besoins locaux.

Quiz — Chapitre 1

4 questions
Question 1 / 4
Quel est le rôle de la couche "Distribution" dans l'architecture Cisco à 3 couches ?
La couche Distribution est le cerveau du réseau: elle route entre les VLANs (inter-VLAN routing), applique les politiques de sécurité (ACL), gère la qualité de service (QoS), et agrège les liens montants des switches d'accès vers le core.
Question 2 / 4
Pourquoi le modèle "collapsed core" (2 couches) est-il recommandé pour les PME ?
Le collapsed core fusionne les couches Core et Distribution en un ou deux switches L3 centraux. Moins d'équipements = moins de coût, moins de complexité, moins de maintenance. Pour une PME de 50-200 personnes, c'est amplement suffisant.
Question 3 / 4
Pourquoi la couche Core ne doit-elle pas effectuer de filtrage ou de routage complexe ?
Le Core est le backbone: sa priorité absolue est la vitesse de transmission. Chaque traitement supplémentaire (filtrage ACL, QoS) ajoute de la latence. Le filtrage et les politiques sont appliqués aux couches Distribution et Access, pas au Core.
Question 4 / 4
Quelle couche connecte directement les postes de travail, imprimantes et téléphones IP ?
La couche Access (accès) est celle qui connecte directement les équipements terminaux (postes de travail, imprimantes, téléphones IP, caméras IP). Elle opère typiquement à la couche 2 (L2) avec des switches non gérés ou gérés simples.

🎬 Guide de production
1
Router-on-a-Stick (4 min) — Un seul lien trunk entre routeur et switch. Sous-interfaces du routeur (interface Fa0/0.10, .20, .30) avec encapsulation dot1Q pour chaque VLAN.
2
Routage inter-VLAN sur switch L3 (5 min) — Interface SVI (Switched Virtual Interface): interface vlan 10, ip address 192.168.10.1 255.255.255.0, no shutdown. Plus performant que Router-on-a-Stick.
3
VTP (VLAN Trunking Protocol) (4 min) — Propager automatiquement les VLANs sur tous les switches du domaine VTP. Modes: Server, Client, Transparent. Danger du mode Server sans prudence.
4
VLAN Voice (VLAN auxiliaire) (3 min) — Configurer un VLAN dédié pour la voix IP (QoS). switchport voice vlan 100 sur les ports avec téléphones IP.

Quiz — Chapitre 2

4 questions
Question 1 / 4
Dans la configuration "Router-on-a-Stick", que signifie "encapsulation dot1Q 10" ?
encapsulation dot1Q 10 dit au routeur que cette sous-interface (ex: Fa0/0.10) doit traiter les trames portant le tag VLAN 10 (protocole IEEE 802.1Q). Le routeur route le trafic VLAN 10 via cette sous-interface.
Question 2 / 4
Qu'est-ce qu'une SVI (Switched Virtual Interface) sur un switch L3 ?
Une SVI (interface vlan X) est une interface logique sur un switch L3 qui représente un VLAN. Elle a une adresse IP et sert de passerelle par défaut pour tous les hôtes de ce VLAN. Le switch L3 route entre les SVIs directement en hardware — bien plus rapide que Router-on-a-Stick.
Question 3 / 4
Quel est le principal danger du mode "VTP Server" mal configuré ?
Un switch VTP Server avec un numéro de révision VTP supérieur à celui du domaine va propager sa base VLAN (peut-être vide ou incorrecte) à tous les switches du domaine, supprimant tous les VLANs existants. Catastrophique. Solution: utiliser le mode VTP Transparent ou VTP version 3 avec mot de passe.
Question 4 / 4
Pourquoi créer un VLAN Voice dédié pour les téléphones IP ?
La voix IP est sensible à la latence et la gigue. En isolant le trafic voix dans un VLAN dédié, on peut appliquer des politiques QoS qui lui donnent priorité sur le trafic données. switchport voice vlan 100 configure automatiquement le port pour supporter deux VLANs (données + voix).

▶
Vidéo 3 — Spanning Tree Protocol — Configuration avancée
Durée : 15 min
▶
Lien YouTube à insérer
Aucun lien configuré
🎬 Guide de production
1
Rappel STP et RSTP (4 min) — Élection du Root Bridge (priorité + adresse MAC), rôles des ports (Root, Designated, Blocked/Alternate).
2
PortFast et BPDU Guard (4 min) — PortFast: ignorer les délais STP sur les ports d'accès (démarrage immédiat). BPDU Guard: désactiver le port si un switch non autorisé y est connecté. Critique pour la sécurité.
3
Choisir le Root Bridge (3 min) — Configurer la priorité STP pour forcer le Root Bridge sur le switch souhaité. spanning-tree vlan X priority 0 (ou 4096).
4
Rapid PVST+ (2 min) — PVST+ = STP par VLAN (Cisco). Rapid PVST+ = RSTP par VLAN. Configuration: spanning-tree mode rapid-pvst.

Quiz — Chapitre 3

4 questions
Question 1 / 4
Quel switch devient Root Bridge lors de l'élection STP ?
L'élection STP se fait en deux temps: 1) Le switch avec la priorité la plus BASSE gagne (défaut: 32768). 2) Si deux switches ont la même priorité, celui avec la plus petite adresse MAC gagne. On configure explicitement le Root Bridge souhaité avec une priorité 0 ou 4096.
Question 2 / 4
Que fait BPDU Guard sur un port d'accès ?
BPDU Guard protège les ports d'accès: si une BPDU (message STP) arrive sur ce port, c'est qu'un switch y est connecté — ce qui n'est pas prévu et potentiellement malveillant. Le port est immédiatement mis en état err-disabled pour protéger la topologie STP.
Question 3 / 4
PortFast sur un port d'accès permet de...
Sans PortFast, un port met 30-50 secondes avant de passer en Forwarding (états: Blocking→Listening 15s→Learning 15s→Forwarding). Un PC met 30 secondes à obtenir son IP DHCP après connexion — inacceptable. PortFast saute directement en Forwarding. Ne jamais activer PortFast sur un port trunk.
Question 4 / 4
Comment forcer un switch Cisco à devenir Root Bridge pour le VLAN 10 ?
spanning-tree vlan X priority 0 fixe la priorité à 0 (minimum), garantissant que ce switch gagne toujours l'élection Root Bridge pour ce VLAN. Alternativement, spanning-tree vlan X root primary configure automatiquement une priorité suffisamment basse pour gagner l'élection actuelle.

EtherChannel / LAG (4 min) — Regrouper 2-8 liens physiques en un seul lien logique. Doubler ou quadrupler la bande passante. Protocoles: PAgP (Cisco propriétaire), LACP (802.3ad, standard).

Quiz — Chapitre 4

4 questions
Question 1 / 4
EtherChannel regroupant 4 liens FastEthernet 100 Mbps donne un débit logique de...
EtherChannel additionne la bande passante: 4 × 100 Mbps = 400 Mbps de bande passante totale sur le lien logique. STP voit ce lien comme un seul port — pas de blocage, toute la bande passante est utilisée.
Question 2 / 4
HSRP (Hot Standby Router Protocol) est utilisé pour...
HSRP crée une IP virtuelle partagée entre deux routeurs (actif + standby). Les hôtes utilisent l'IP virtuelle comme passerelle. Si le routeur actif tombe en panne, le standby prend l'IP virtuelle — les hôtes ne changent pas leur configuration. Basculement en quelques secondes.
Question 3 / 4
Dans un contexte haïtien, pourquoi configurer une redondance WAN avec 2 FAI différents (Natcom + Digicel) ?
La redondance WAN avec deux FAI différents est cruciale en Haïti où les coupures de service FAI sont relativement fréquentes. Si Natcom a une panne sur son backbone, Digicel reste disponible. Le routeur bascule automatiquement le trafic vers l'interface WAN active.
Question 4 / 4
Quel protocole EtherChannel est standard IEEE (non propriétaire Cisco) ?
LACP (IEEE 802.3ad) est le standard ouvert pour l'agrégation de liens. Il fonctionne entre équipements de marques différentes. PAgP est propriétaire Cisco — uniquement entre équipements Cisco. En déploiement multi-vendor, toujours utiliser LACP.

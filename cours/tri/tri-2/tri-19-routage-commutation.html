2.1 Méthodes de commutation

MéthodeFonctionnementAvantageInconvénient
Store-and-ForwardReçoit la trame complète, vérifie le CRC, puis transmetÉlimine les trames corrompues (0 erreur sortant)Latence plus élevée
Cut-ThroughCommence à transmettre dès que l'adresse MAC destination est lue (6 octets)Latence très faiblePeut transmettre des trames corrompues
Fragment-FreeAttend les 64 premiers octets avant de transmettreÉlimine les collisions de fragmentsCompromis entre les deux
📌 Standard actuel Les switches Cisco modernes (Catalyst 2960, 3750, 9200) utilisent Store-and-Forward par défaut. C'est la méthode recommandée pour les réseaux de production car elle garantit la qualité des données transmises.

2.2 Domaines de collision et de diffusion

ÉquipementDomaines de collisionDomaines de diffusionCouche OSI
Hub1 seul (partagé entre tous les ports)1 seulCouche 1
Switch1 par port (full duplex = élimine les collisions)1 seul (tous les ports dans le même domaine)Couche 2
Routeur1 par interface1 par interface (isole les broadcasts)Couche 3
Switch L3 / VLAN1 par port1 par VLAN (les VLANs segmentent les broadcasts)Couche 2 + 3

🎬 Guide de production
1
Pourquoi STP ? (4 min) — Tempêtes de broadcast sans STP. Boucles de couche 2. Démonstration : 3 switches interconnectés sans STP → réseau inutilisable.
2

4.1 États des ports STP

ÉtatReçoit BPDUEnvoie BPDUApprend MACTransfert donnéesDurée
Blocking✅❌❌❌Max Age (20s)
Listening✅✅❌❌Forward Delay (15s)
Learning✅✅✅❌Forward Delay (15s)
Forwarding✅✅✅✅Normal (indéfini)
Disabled❌❌❌❌Port admin shutdown
⚡ RSTP — Rapid STP (802.1w) RSTP réduit la convergence de ~50s (STP classique) à moins de 1 seconde. Il remplace les états Listening et Blocking par un seul état "Discarding" et utilise des mécanismes de négociation plus rapides. PVST+ (Per-VLAN Spanning Tree Plus) est la version Cisco de STP — un arbre par VLAN, permettant le load balancing.

4.2 Configuration STP — Forcer le Root Bridge

Cisco IOS — STP PVST+
! Forcer SW-Core comme Root Bridge VLAN 10, 20
SW-Core(config)# spanning-tree vlan 10,20 priority 4096    ← valeur basse = priorité haute
! Méthode recommandée :
SW-Core(config)# spanning-tree vlan 10,20 root primary     ← ajuste auto à 24576

! PortFast + BPDU Guard sur ports hôtes (pas vers d'autres switches)
SW(config)# interface range GigabitEthernet0/1 - 20
SW(config-if-range)# spanning-tree portfast
SW(config-if-range)# spanning-tree bpduguard enable
SW(config-if-range)# exit

! Activer PortFast par défaut sur tous les ports access
SW(config)# spanning-tree portfast default

! Vérification STP
SW# show spanning-tree vlan 10
SW# show spanning-tree summary
  Root bridge for: VLAN0010, VLAN0020
  This bridge is the root

5.3 Principe du Longest Prefix Match

🎯 Règle du match le plus long Le routeur choisit TOUJOURS la route avec le préfixe le plus long (le plus spécifique) qui correspond à la destination.

Exemple : Pour envoyer un paquet vers 192.168.10.55, si la table contient :
• 192.168.10.0/24 → Gi0/0
• 192.168.10.48/28 → Gi0/2 (192.168.10.48 à .63)
• 0.0.0.0/0 → Internet

Le routeur choisit /28 (plus spécifique) car .55 est dans la plage .48–.63 → route vers Gi0/2.

7.3 Wildcard Mask — Calcul rapide

📐 Wildcard = inverse du masque de sous-réseau Méthode : Soustraire chaque octet du masque de 255.

255.255.255.0 → Wildcard = 0.0.0.255
255.255.255.128 → Wildcard = 0.0.0.127
255.255.255.252 → Wildcard = 0.0.0.3
255.255.0.0 → Wildcard = 0.0.255.255

Exemple OSPF : Annoncer 10.0.0.0/30 → network 10.0.0.0 0.0.0.3 area 0

9.2 Configuration ACL — Standard et Étendue

Cisco IOS — ACLs Standard et Étendue
! === ACL STANDARD (Named) ===
! Bloquer le réseau Étudiants de l'accès au serveur de gestion
R(config)# ip access-list standard BLOCK-ETUDIANTS
R(config-std-nacl)# deny 192.168.10.0 0.0.0.255
R(config-std-nacl)# permit any
R(config-std-nacl)# exit

! Appliquer sur l'interface near destination, direction inbound
R(config)# interface GigabitEthernet0/2
R(config-if)# ip access-group BLOCK-ETUDIANTS in
R(config-if)# exit

! === ACL ÉTENDUE (Named) ===
! Permettre SSH depuis le réseau Gestion, bloquer Telnet
R(config)# ip access-list extended SECURITE-VTY
R(config-ext-nacl)# permit tcp 192.168.30.0 0.0.0.255 any eq 22  ← SSH ok
R(config-ext-nacl)# deny tcp any any eq 23                        ← Telnet bloqué
R(config-ext-nacl)# permit ip any any                              ← tout le reste ok
R(config-ext-nacl)# exit

! Appliquer sur les lignes VTY
R(config)# line vty 0 15
R(config-line)# access-class SECURITE-VTY in
R(config-line)# exit

! ACL étendue — Bloquer ping (ICMP) d'un réseau
R(config)# ip access-list extended BLOCK-PING
R(config-ext-nacl)# deny icmp 192.168.10.0 0.0.0.255 any
R(config-ext-nacl)# permit ip any any
R(config-ext-nacl)# exit

! Vérification
R# show access-lists                ← toutes les ACLs + compteurs
R# show ip interface GigabitEthernet0/1  ← ACLs appliquées

9.3 Règles essentielles des ACL

⚠️ Règles à ne jamais oublier 1. Implicit deny all : Toute ACL se termine par un "deny ip any any" implicite. Si un paquet ne correspond à aucune règle, il est BLOQUÉ. Toujours ajouter "permit ip any any" si nécessaire.
2. Première correspondance gagne : Les ACE sont lues en ordre. La première règle qui correspond s'applique. Les règles suivantes sont ignorées. Ordre = logique d'abord spécifique → général.
3. Placement ACL Standard : Près de la DESTINATION (car elle ne filtre que la source — mettre près de la source bloquerait le trafic vers toutes les destinations).
4. Placement ACL Étendue : Près de la SOURCE (filtre précis, évite d'inutilement router des paquets qui seront bloqués plus loin).

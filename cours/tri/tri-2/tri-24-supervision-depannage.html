Quiz — Chapitre 1

4 questions
Question 1 / 4
Quelle version de SNMP est recommandée pour la sécurité en production ?
SNMPv3 ajoute l'authentification (MD5 ou SHA) et le chiffrement (DES ou AES) des données. SNMPv1 et v2c transmettent la communauté (le mot de passe) en clair — lisible par wireshark. En production, toujours utiliser SNMPv3.
Question 2 / 4
Qu'est-ce qu'un "Trap SNMP" ?
Un Trap est une notification envoyée par l'agent SNMP (sur l'équipement: routeur, switch, serveur) vers le manager SNMP (serveur de supervision) quand un événement survient: lien qui tombe, CPU > 90%, authentification SNMP incorrecte. C'est la base du monitoring proactif.
Question 3 / 4
La communauté SNMP "public" en lecture seule sur un équipement de production est...
"Public" est la communauté SNMP par défaut connue de tous. N'importe qui sur le réseau peut l'utiliser pour lire toutes les informations SNMP de l'équipement (interfaces, routes, voisins, configuration). Toujours changer la communauté par défaut avec un nom difficile à deviner.
Question 4 / 4
Un OID SNMP (Object Identifier) permet de...
Un OID est un chemin unique dans la MIB. Exemple: 1.3.6.1.2.1.1.3.0 = sysUpTime (durée de fonctionnement du système). Les logiciels de monitoring utilisent les OIDs pour collecter des métriques spécifiques des équipements.

🎬 Guide de production
1
Introduction à Wireshark (3 min) — Analyseur de protocole (sniffer). Comment capturer sur la bonne interface. Mode promiscuité.
2
Filtres d'affichage (5 min) — ip.addr == 192.168.1.1 (filtrer par IP). tcp.port == 80 (filtrer par port). http (filtrer le protocole HTTP). arp (voir les requêtes ARP). !arp && !dns (exclure ARP et DNS).

4
Identifier des anomalies (5 min) — Beaucoup de retransmissions TCP (problème de réseau). ARP gratuit (changement d'IP ou attaque). Broadcast storm (loop réseau). Connexions vers des IPs suspectes.

Quiz — Chapitre 2

4 questions
Question 1 / 4
Wireshark capture le trafic sur une interface en mode "promiscuité". Que signifie ce mode ?
En mode normal, une carte réseau ignore les trames qui ne lui sont pas destinées. En mode promiscuité, elle capture toutes les trames visibles sur le segment réseau. Cela permet à Wireshark d'analyser le trafic d'autres hôtes (si on est sur un hub ou si le switch a un SPAN port configuré).
Question 2 / 4
Que signifient beaucoup de "TCP Retransmission" dans une capture Wireshark ?
Les retransmissions TCP indiquent des pertes de paquets: l'émetteur n'a pas reçu l'accusé de réception (ACK) et retransmet le segment. Causes possibles: lien saturé, câble défectueux, switch avec erreurs, pare-feu qui drop des paquets.
Question 3 / 4
Comment filtrer dans Wireshark pour voir uniquement le trafic d'un hôte spécifique (192.168.1.50) ?
ip.addr == 192.168.1.50 est le filtre d'affichage correct. Il montre tout le trafic où 192.168.1.50 est soit la source soit la destination. Pour uniquement la source: ip.src == 192.168.1.50. Pour uniquement la destination: ip.dst == 192.168.1.50.
Question 4 / 4
Voir de nombreux "Gratuitous ARP" dans Wireshark peut indiquer...
Un ARP gratuit est un ARP request où la source et la destination IP sont identiques — l'hôte annonce son IP à tout le réseau. Légitime: quand un hôte change d'IP (DHCP). Suspect: si répété fréquemment ou depuis plusieurs sources pour la même IP = possible ARP spoofing (attaque man-in-the-middle).

🎬 Guide de production
1
La méthode divide and conquer (3 min) — Diviser le réseau en deux: le problème est-il dans la moitié A ou B? Puis diviser à nouveau. Localise la panne en log(N) étapes.
2
Scénario 1 — Panne partielle VLAN (5 min) — Certains PCs du VLAN 20 ne peuvent pas communiquer. Démarche: show vlan brief, vérifier les ports, vérifier le trunk, vérifier le routage inter-VLAN.
3

4
Scénario 3 — DNS résolution intermittente (2 min) — Parfois les sites web s'ouvrent, parfois non. nslookup avec debug, vérifier les serveurs DNS secondaires.

Quiz — Chapitre 3

4 questions
Question 1 / 4
La méthode "divide and conquer" pour le dépannage réseau consiste à...
Divide and conquer: si 20 switches, vérifier le switch central (switch 10). Si le problème est dans la première moitié, vérifier switch 5. Puis switch 2 ou 8. On localise la panne en 4-5 étapes au lieu de 20. Cette méthode est aussi appelée "binary search troubleshooting".
Question 2 / 4
La commande "show interfaces" sur un switch Cisco affiche des "input errors". Cela indique...
Les input errors (CRC errors, runts, giants, frame check sequence errors) indiquent des problèmes au niveau physique: câble abîmé, connecteur mal sertir, interférence électromagnétique, problème de duplex/vitesse. Commencer toujours par vérifier le câble physiquement.
Question 3 / 4
Un duplex mismatch entre un switch et un PC provoque...
Duplex mismatch: une extrémité en Full Duplex, l'autre en Half Duplex. La partie HD détecte des "collisions" quand la partie FD envoie pendant qu'elle émet aussi. Résultat: nombreuses retransmissions, connexion lente. Solution: configurer explicitement le duplex et la vitesse sur les deux extrémités, ou utiliser auto-negotiate cohérent.
Question 4 / 4
Si "show ip ospf neighbor" n'affiche aucun voisin alors qu'un lien OSPF est configuré, la première cause à vérifier est...
OSPF ne forme pas de voisinage si les interfaces ne sont pas dans le même sous-réseau, ou si les timers Hello/Dead ne correspondent pas (le réseau annoncé dans OSPF ne correspond pas à l'interface). Vérifier: show ip ospf interface (timer hello, sous-réseau, type réseau).

Quiz — Chapitre 4

4 questions
Question 1 / 4
Pourquoi un SPAN port (Port Mirroring) est-il nécessaire pour analyser le trafic d'un serveur spécifique ?
Sur un réseau switché, un hôte ne voit que les trames qui lui sont adressées (unicast) + les broadcasts. Pour voir le trafic d'un autre hôte, il faut un SPAN qui copie ses trames vers un port dédié à l'analyse. Sans SPAN, impossible d'analyser le trafic d'un serveur avec Wireshark depuis un autre PC.
Question 2 / 4
NetFlow sur un routeur Cisco permet de...
NetFlow collecte des statistiques sur tous les flux réseau: IP source, IP destination, port source, port destination, protocole, volume de données. Très utile pour identifier qui consomme la bande passante, détecter des comportements anormaux, et planifier les upgrades.
Question 3 / 4
La commande CDP "show cdp neighbors detail" affiche...
show cdp neighbors detail affiche pour chaque voisin Cisco: le nom du device, le modèle, la version IOS, les adresses IP sur toutes les interfaces, et les interfaces connectées. Très utile pour cartographier rapidement une topologie inconnue sans documentation.
Question 4 / 4
Zabbix est un outil de supervision réseau qui...
Zabbix est 100% open source et gratuit, sans limite du nombre d'équipements supervisés. Il supporte SNMP, ICMP, agents Zabbix (Windows/Linux), JMX, et dispose d'une interface web complète avec tableaux de bord, graphiques historiques, alertes configurables par email/SMS.

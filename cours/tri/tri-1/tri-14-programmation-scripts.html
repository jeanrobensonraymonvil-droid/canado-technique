Énoncé de la compétence

Développer des scripts shell.

Présentation du module

Ce module, offert en première année, introduit la programmation de scripts shell sur un système d'exploitation approprié. Dans le cadre de son métier, le technicien en réseaux informatiques doit réaliser certaines séries de scripts pour principalement lancer et coordonner l'exécution de programmes afin d'automatiser les tâches.

À la fin de ce module, l'étudiant sera en mesure de concevoir de petits programmes sous forme de fichiers script pour automatiser des tâches informatiques de façon logique et structurée.

Ce module s'inscrit dans la continuité de TRI-05 (Système d'exploitation). Les compétences acquises ici serviront directement dans TRI-10 (Installation d'un poste), TRI-12 (Dépannage d'un poste) et les modules réseau de deuxième année, où l'automatisation des configurations est une pratique courante dans les entreprises haïtiennes comme Natcom, Digicel ou les institutions financières telles que Sogebank.

Éléments de la compétence

  1. Analyser les besoins en ce qui a trait au développement du script shell.
  2. Déterminer la logique et coder le script shell.
  3. Tester le script shell.

Qu'est-ce qu'un script ?

Un script est un fichier texte contenant une suite de commandes que le système d'exploitation exécute séquentiellement, sans intervention humaine. Contrairement à un programme compilé, un script est interprété ligne par ligne à l'exécution.

Le technicien en réseaux informatiques passe beaucoup de temps sur des tâches répétitives : créer des comptes, sauvegarder des données, redémarrer des services. Un script bien écrit exécute ces tâches en quelques secondes, à n'importe quelle heure — même à 3h du matin lors d'une fenêtre de maintenance chez Natcom ou Digicel.

💡 Définition Un script shell est un programme interprété par le shell (interpréteur de commandes) du système d'exploitation. Sur Windows : PowerShell (.ps1). Sur Linux/macOS : Bash (.sh). Les deux sont des outils essentiels du technicien réseau moderne.

Pourquoi automatiser ? Exemples concrets

Tâche manuelleAvec un scriptGain
Créer 50 comptes utilisateursNew-ADUser en boucle4 h → 2 min
Sauvegarder 200 fichiers avant coupureScript planifié à 22h000 h d'intervention
Vérifier l'espace disque sur 10 serveursGet-PSDrive + rapportRapport en 30 s
Renommer 300 photos selon la dateScript + Get-ChildItemAucune erreur humaine

🌴 Contexte Haïti Dans les entreprises haïtiennes (Sogebank, MSPP, hôtels), Windows Server est dominant : PowerShell est le choix prioritaire. Sur les équipements réseau Cisco présents dans le cursus CCNA, les scripts Python et Bash complètent l'outillage. Vous utiliserez les deux au fil du programme TRI.

Mon premier script PowerShell

Voici la structure minimale d'un script PowerShell professionnel. Utilisez le terminal ci-dessus pour tester les exemples :

# ═══════════════════════════════════
# Script : SaluerUtilisateur.ps1
# Auteur : Jean Dupont — Canado CFPH
# Date : 2025-01-15
# But : Afficher un message de bienvenue
# ═══════════════════════════════════

$nom = Read-Host "Quel est ton nom ?"
$heure = (Get-Date).Hour

if ($heure -lt 12) {
    Write-Host "Bonjour, $nom !" -ForegroundColor Green
} else {
    Write-Host "Bonsoir, $nom !" -ForegroundColor Yellow
}
✅ Bonne pratique Tout script professionnel commence par un en-tête commenté (nom, auteur, date, but). C'est une exigence dans les entreprises comme dans vos évaluations. Prenez cette habitude dès maintenant.

ScriptFichier texte contenant une suite de commandes exécutées séquentiellement par le système, sans intervention humaine.
Langage interprétéLangage dont le code est lu et exécuté ligne par ligne à l'exécution, sans compilation préalable (ex. PowerShell, Bash, Python).
AutomatisationFait de confier à un script des tâches répétitives pour gagner du temps et éviter les erreurs humaines.
ShellInterpréteur de commandes (PowerShell sous Windows, Bash sous Linux) qui exécute les scripts.

📌 Bon à savoir
  • Un script automatise les tâches répétitives : ce qui te prend une heure à la main se fait en quelques secondes, sans erreur.
  • Contrairement à un programme compilé, un script est interprété ligne par ligne : pas besoin de le compiler avant de l'exécuter.
  • PowerShell sous Windows, Bash sous Linux : ce sont les shells que le technicien réseau utilise au quotidien.
  • Coder n'est pas réservé aux développeurs : pour un technicien TRI, automatiser sauvegardes et vérifications est une compétence clé.

Pourquoi analyser avant de coder ?

Une erreur classique du débutant : ouvrir l'éditeur et taper du code avant de comprendre le problème. Un script mal analysé produit un résultat qui ne correspond pas aux attentes du client — même s'il s'exécute sans erreur. L'analyse des besoins est la première compétence exigée à l'évaluation de sanction de TRI-14 (10 points sur 100).

La fiche d'analyse des besoins

QuestionCe qu'elle révèleExemple (script de sauvegarde)
Qui ?L'utilisateur cible et ses droitsTechnicien avec droits admin
Quoi ?Les données traitées, le résultat attenduFichiers .docx → dossier archive
Quand ?Fréquence, planificationChaque nuit à 23h00
Où ?Chemins, serveurs, réseaux impliquésD:\Docs → \\NAS\archives\
Pourquoi ?Objectif business derrière la demandeProtéger contre coupure de courant
Comment ?Contraintes techniques, OS, droitsWindows 10, PS 5.1, droits réseau

Identifier les entrées, traitements et sorties

Tout script peut se modéliser selon trois composantes fondamentales :

📥
ENTRÉES
Données fournies au script : paramètres, fichiers, saisies utilisateur, variables d'environnement
⚙️
TRAITEMENTS
Ce que le script fait : calculs, comparaisons, copies, transformations, appels à des services
📤
SORTIES
Résultats produits : fichiers créés, messages à l'écran, journaux, modifications de la base de données
📋 Exemple complet — Script de rapport d'espace disque Entrées : liste des serveurs (fichier texte), seuil d'alerte en Go (paramètre)
Traitements : interroger chaque serveur, comparer l'espace libre au seuil, catégoriser (OK / ALERTE / CRITIQUE)
Sorties : fichier rapport CSV, e-mail d'alerte si seuil dépassé, message à l'écran

Évaluer la faisabilité

Avant de coder, répondez honnêtement à ces questions :

  • Le script a-t-il les droits suffisants pour réaliser les actions demandées ?
  • L'environnement cible a-t-il la version du langage requise ?
  • Les chemins réseau sont-ils accessibles en dehors des heures ouvrées ?
  • Les données d'entrée sont-elles dans un format exploitable ?
  • Y a-t-il des contraintes légales ou de confidentialité à respecter ?
⚠️ Erreur fréquente Supposer que le script tournera toujours avec des droits administrateur. En production, les scripts sont souvent exécutés sous un compte de service aux droits limités. Analyser les droits nécessaires fait partie de l'analyse des besoins.
🔑 Termes clés
Analyse des besoinsPremière étape : comprendre précisément le problème, l'utilisateur cible et le résultat attendu, AVANT d'écrire du code.
Entrées / sortiesLes entrées sont les données que le script reçoit ; les sorties, le résultat qu'il produit. À définir avant de coder.
Fiche d'analyseDocument qui répond à : qui ? quoi ? avec quelles entrées ? quelles sorties ? sous quelles contraintes ?
FaisabilitéÉvaluation de la possibilité technique de réaliser le script avec les outils et le temps disponibles.
Cahier des chargesFormalisation du besoin : objectif du script, contraintes, format des entrées et des sorties attendues.
Cas limitesSituations particulières à prévoir (fichier vide, valeur manquante, erreur) pour que le script reste fiable.
📌 Bon à savoir
  • L'erreur du débutant : taper du code avant de comprendre le problème. Un script peut s'exécuter sans erreur et pourtant être faux.
  • Avant de coder, définis clairement les entrées (ce que le script reçoit) et les sorties (ce qu'il doit produire).
  • L'analyse des besoins compte pour 10 points sur 100 à l'évaluation de TRI-14 : ne la néglige jamais.
  • Pense aux cas limites dès l'analyse : fichier vide, valeur absente, droit refusé. C'est là que les scripts fragiles échouent.

La logique avant le code

Un algorithme est une suite finie et ordonnée d'instructions permettant de résoudre un problème. Comme une recette de cuisine : les ingrédients (entrées), les étapes (traitements) et le plat fini (sortie). En TRI-14, maîtriser l'algorithmique est central : 65 des 100 points de l'épreuve de sanction portent sur l'algorithme et sa traduction en code.

Les trois structures de contrôle fondamentales

StructureDescriptionExemple PowerShell
Séquence Instructions exécutées l'une après l'autre, dans l'ordre $a = 5
$b = $a + 3
Write-Host $b
Sélection
(condition)		 Choisir entre deux chemins selon une condition vraie ou fausse if ($note -ge 70) {
 "Reçu"
} else {
 "Recalé"
}
Itération
(boucle)		 Répéter des instructions tant qu'une condition est vraie, ou un nombre défini de fois for ($i=1; $i -le 10; $i++) {
 Write-Host $i
}
📝 Pseudocode — Conventions Le pseudocode est une description informelle d'un algorithme en langage naturel structuré. En TRI-14, on utilise la notation francophone :

DÉBUT
  LIRE note
  SI note ≥ 70 ALORS
    AFFICHER "Reçu"
  SINON
    AFFICHER "Recalé"
  FIN SI
FIN

Symboles de l'ordinogramme

SymboleFormeUsage
Début / FinOvale / ArrondiMarque le début et la fin du programme
TraitementRectangleCalcul, affectation, opération
DécisionLosangeQuestion à réponse OUI/NON (condition)
Entrée / SortieParallélogrammeLecture de données ou affichage
ConnecteurCercleRelier des parties de l'ordinogramme
🔑 Règle d'or N'ouvrez jamais l'éditeur avant d'avoir dessiné votre ordinogramme. À l'épreuve de sanction, l'algorithme (ordinogramme + pseudocode) vaut 35 points. Un bon algorithme se traduit facilement en code. Un mauvais algorithme donne un mauvais code, même techniquement correct.

Exemple complet : vérifier si un dossier est vide

Pseudocode :

DÉBUT
  LIRE chemin_dossier
  SI dossier_existe(chemin_dossier) ALORS
    compteur ← nombre_fichiers(chemin_dossier)
    SI compteur = 0 ALORS
      AFFICHER "Le dossier est vide"
    SINON
      AFFICHER "Le dossier contient " + compteur + " fichier(s)"
    FIN SI
  SINON
    AFFICHER "Erreur : dossier introuvable"
  FIN SI
FIN

Traduction PowerShell (testez dans le terminal du chapitre 1) :

$chemin = "C:\TRI14\rapports"
if (Test-Path $chemin) {
  $compteur = (Get-ChildItem $chemin).Count
  if ($compteur -eq 0) {
    Write-Host "Le dossier est vide" -ForegroundColor Yellow
  } else {
    Write-Host "Le dossier contient $compteur fichier(s)" -ForegroundColor Green
  }
} else {
  Write-Host "Erreur : dossier introuvable" -ForegroundColor Red
}
🔑 Termes clés
AlgorithmeSuite finie et ordonnée d'instructions permettant de résoudre un problème ; comme une recette de cuisine.
PseudocodeDescription d'un algorithme en langage proche du français, indépendante du langage de programmation.
OrdinogrammeReprésentation graphique d'un algorithme à l'aide de symboles (début, traitement, décision, fin).
SéquenceStructure de contrôle où les instructions s'exécutent l'une après l'autre, dans l'ordre.
Condition (sélection)Structure qui exécute des instructions différentes selon qu'un test est vrai ou faux (if / else).
Boucle (répétition)Structure qui répète des instructions tant qu'une condition est vraie (while, for, ForEach).
📌 Bon à savoir
  • On conçoit la logique AVANT d'écrire le code : un algorithme se pense en pseudocode ou en ordinogramme, indépendamment du langage.
  • Un algorithme, c'est une recette : des entrées (ingrédients), des traitements (étapes) et une sortie (le plat fini).
  • Les trois structures fondamentales suffisent à tout exprimer : la séquence, la condition et la boucle.
  • À l'évaluation de TRI-14, 65 points sur 100 portent sur l'algorithme et sa traduction en code : c'est le cœur du module.

Variables et types de données

En PowerShell, une variable commence toujours par $. Le typage est dynamique : PowerShell déduit automatiquement le type de la valeur assignée.

TypeExempleUsage
Entier$age = 22Compteurs, ports, tailles
Décimal$ratio = 3.14Pourcentages, calculs
Chaîne$nom = "Canado"Noms, chemins, messages
Booléen$ok = $trueFlags, conditions
Tableau$ips = @("192.168.1.1","10.0.0.1")Listes de serveurs, fichiers
Table de hachage$user = @{Nom="Jean";Age=25}Structures de données

Opérateurs de comparaison PowerShell

⚠️ Attention — Syntaxe différente de C/Java PowerShell utilise des opérateurs textuels, pas des symboles : -eq (égal), -ne (différent), -gt (plus grand), -lt (plus petit), -ge (plus grand ou égal), -le (plus petit ou égal), -and, -or, -not.

Structures de boucles

BoucleSyntaxeQuand l'utiliser
Forfor ($i=1; $i -le 10; $i++)Nombre d'itérations connu

Pipeline (|)Get-ChildItem | ForEach-ObjectStyle PowerShell natif — très efficace

Fonctions

Une fonction est un bloc de code réutilisable. Elle prend des paramètres et peut retourner une valeur. En PowerShell, les fonctions suivent la convention Verbe-Nom :

function Get-EspaceLibe {
  param([string]$disque = "C:")
  $info = Get-PSDrive -Name $disque.TrimEnd(":")
  return [math]::Round($info.Free / 1GB, 2)
}

# Appel de la fonction :
$libre = Get-EspaceLibe -disque "C:"
Write-Host "Espace libre : $libre Go"

Notion d'objet — La force de PowerShell

Contrairement à Bash qui manipule du texte, PowerShell manipule des objets. Chaque cmdlet retourne des objets avec des propriétés et des méthodes :

# Get-Date retourne un objet DateTime, pas du texte
$date = Get-Date
$date.Year # propriété : retourne 2025
$date.DayOfWeek # propriété : retourne Monday...
$date.AddDays(7) # méthode : retourne la date dans 7 jours
💡 Conseil pratique Utilisez Get-Member pour découvrir toutes les propriétés et méthodes d'un objet : Get-Date | Get-Member. C'est votre outil de découverte le plus puissant en PowerShell.
🔑 Termes clés
VariableEspace nommé qui stocke une valeur ; en PowerShell, elle commence toujours par le signe dollar (ex. $nom).
Type de donnéesNature de la valeur stockée : entier, décimal, chaîne de caractères, booléen, tableau, table de hachage.
Typage dynamiquePowerShell déduit automatiquement le type d'une variable à partir de la valeur qu'on lui assigne.
TableauCollection ordonnée de valeurs, déclarée avec @( ) ; sert à stocker des listes (serveurs, fichiers).
FonctionBloc de code nommé et réutilisable qui réalise une tâche précise et peut renvoyer un résultat.
Table de hachageCollection de paires clé-valeur, déclarée avec @{ } ; sert à structurer des données (ex. un utilisateur).
📌 Bon à savoir
  • En PowerShell, toute variable commence par $ : $age, $nom, $serveurs. C'est la règle de base de la syntaxe.
  • Le typage est dynamique : PowerShell devine le type selon la valeur. $age = 22 est un entier, $nom = "Canado" une chaîne.
  • Un tableau @( ) stocke une liste ordonnée ; une table de hachage @{ } stocke des paires clé-valeur.
  • Une fonction regroupe un bloc de code réutilisable : tu l'écris une fois et tu l'appelles autant de fois que nécessaire.

Règles et conventions de codage

  • Nommage des variables : $nomCamelCase pour les variables, Verbe-Nom pour les fonctions (Get-Report, Set-Config).
  • Indentation : 4 espaces par niveau de profondeur (pas de tabulations).
  • Commentaires : # pour les lignes simples, <# ... #> pour les blocs. Commentez le "pourquoi", pas le "quoi".
  • Longueur des lignes : 80 à 120 caractères maximum. Utilisez le backtick ` pour couper une longue ligne.
  • Un seul rôle par fonction : une fonction qui fait une chose, et une chose bien.

Script complet — Rapport d'espace disque

<#
.SYNOPSIS
  Génère un rapport d'espace disque pour un serveur local.
.AUTHOR : Étudiant TRI-14 — Canado CFPH
.VERSION : 1.0 — 2025-01-15
#>
param(
  [int]$SeuilAlerte = 20 # Go libres minimum
)

Set-StrictMode -Version Latest
$ErrorActionPreference = "Stop"

function Get-StatutDisque {
  param([double]$libreGo, [int]$seuil)
  if ($libreGo -lt $seuil) { return "⚠ ALERTE" }
  else { return "✓ OK" }
}

try {
  $disques = Get-PSDrive -PSProvider FileSystem
  foreach ($d in $disques) {
    $libre = [math]::Round($d.Free / 1GB, 2)
    $statut = Get-StatutDisque -libreGo $libre -seuil $SeuilAlerte
    Write-Host "[$statut] Disque $($d.Name): $libre Go libres"
  }
} catch {
  Write-Host "Erreur : $_" -ForegroundColor Red
}

Les trois types d'erreurs

Démarche méthodique de test

L'épreuve de sanction exige une démarche méthodique. Voici le protocole à suivre :

1
Test des données valides : vérifier que le script produit le bon résultat avec des entrées correctes et représentatives.
2
Test des cas limites : tester les valeurs aux bornes (0, 100, liste vide, dossier manquant, très grand nombre).
3
Test des données invalides : simuler de mauvaises entrées (lettres à la place de chiffres, chemin inexistant, valeur nulle).
4
Validation utilisateur : faire tester le script par le "client" (un camarade ou le professeur) pour confirmer que le résultat correspond à ses attentes.

  • Un script n'est terminé que lorsqu'il est validé : il doit répondre au besoin initial sur des données réelles.

Énoncé de la compétence

Créer et exploiter des bases de données.

Présentation du module

À la fin de ce module, l'étudiant sera capable de créer une base de données simple, de l'alimenter, d'en extraire et d'en manipuler les données avec le langage SQL, à l'aide d'un SGBD (Access, MySQL). Dans le contexte haïtien, la compétence s'applique aux PME (gestion de stock, registre de clients) comme aux institutions et ONG. Le module prépare aussi TRI-18 (Installation de serveur) et TRI-20 (Configuration des serveurs).

Éléments de la compétence

  1. Analyser les besoins.
  2. Concevoir la base de données.
  3. Traiter les données.
  4. Adapter la structure à de nouveaux besoins.
  5. Documenter la base de données.

🔑 Termes clés
Base de données (BD) — Ensemble structuré d'informations stocké sur un support informatique.
SGBD — Système de Gestion de Bases de Données : le logiciel qui gère la BD (ex. MySQL, Access).
Table — Ensemble de données de même nature, organisées en lignes et colonnes.
Champ — Colonne d'une table (un attribut, ex. : nom, téléphone).
Enregistrement — Ligne d'une table (un tuple) décrivant un élément.
Clé primaire — Champ qui identifie de façon unique chaque enregistrement.
Modèle relationnel — Organisation des données en tables reliées par des clés (Codd, 1970).

1.1 Qu'est-ce qu'une base de donn\u00e9es ?

Une base de donn\u00e9es est un ensemble structur\u00e9 d'informations, stock\u00e9 sur un support informatique, accessible \u00e0 plusieurs utilisateurs et g\u00e9r\u00e9 par un logiciel sp\u00e9cialis\u00e9 : le SGBD (Syst\u00e8me de Gestion de Bases de Donn\u00e9es). Pense au registre d'une \u00e9cole \u00e0 Port-au-Prince : des cahiers de noms, de fili\u00e8res, de r\u00e9sultats \u2014 difficiles \u00e0 fouiller, faciles \u00e0 perdre. Une BD r\u00e9sout tout cela.

1.2 De la bureautique \u00e0 la base de donn\u00e9es

\U0001f309 Passerelle TRI-08 \u2192 TRI-11En bureautique (TRI-08), un tableur comme Excel stocke des donn\u00e9es \u00e0 plat, dans une feuille. Une base de donn\u00e9es, elle, les structure : plusieurs tables reli\u00e9es, sans redondance, avec des r\u00e8gles d'int\u00e9grit\u00e9 et un acc\u00e8s simultan\u00e9. Le tableur range ; la base de donn\u00e9es organise et prot\u00e8ge.

1.3 Les quatre propri\u00e9t\u00e9s d'une BD

Propri\u00e9t\u00e9Signification
Coh\u00e9renceLes donn\u00e9es respectent des r\u00e8gles d\u00e9finies (ex. note \u2264 100)
Non-redondanceChaque information n'est saisie qu'une seule fois
PartageablePlusieurs utilisateurs y acc\u00e8dent en m\u00eame temps
Int\u00e9grit\u00e9Les donn\u00e9es restent exactes et valides dans le temps

1.4 Anatomie et SGBD courants

Une BD relationnelle est faite de tables. Chaque ligne est un enregistrement, chaque colonne un champ, et la cl\u00e9 primaire identifie chaque ligne de fa\u00e7on unique. Les principaux SGBDR : MySQL et MariaDB (gratuits, serveurs), Microsoft Access (PME, interface graphique), PostgreSQL, SQLite.

\U0001f1ed\U0001f1f9 En Ha\u00eftiDans les PME et institutions, Access reste tr\u00e8s r\u00e9pandu pour son interface conviviale. Sur les serveurs (Natcom, Digicel, banques), MySQL/MariaDB dominent.
📌 Bon à savoir
  • Le SGBD est le logiciel qui gère la base ; la base, ce sont les données structurées.
  • Excel stocke à plat ; une base de données structure et relie sans redondance.
  • La clé primaire est unique et non nulle ; souvent un identifiant auto-incrémenté.
  • Quatre propriétés : cohérence, non-redondance, partage, intégrité.

🔑 Termes clés
Normalisation — Structurer les tables pour éviter redondances et anomalies.

2.1 Analyser avant de concevoir

Avant de toucher au clavier, on comprend le besoin : quelles donn\u00e9es stocker, qui les utilise, quels rapports produire, quelles r\u00e8gles m\u00e9tier ? Une conception b\u00e2cl\u00e9e provoque redondances et incoh\u00e9rences difficiles \u00e0 corriger ensuite.

2.2 La normalisation

FormeR\u00e8gle
1NFChaque champ contient une seule valeur (atomique) \u2014 pas de \u00ab Jean, Marie \u00bb dans un champ
2NFChaque colonne non-cl\u00e9 d\u00e9pend de TOUTE la cl\u00e9 primaire
3NFAucune colonne non-cl\u00e9 ne d\u00e9pend d'une autre colonne non-cl\u00e9

2.3 Relations et cardinalit\u00e9s

Les tables sont reli\u00e9es par des cl\u00e9s \u00e9trang\u00e8res. Trois cardinalit\u00e9s :

  • 1:1 \u2014 rare (un employ\u00e9, un badge).
  • 1:N \u2014 un client a plusieurs commandes ; la cl\u00e9 \u00e9trang\u00e8re est c\u00f4t\u00e9 \u00ab plusieurs \u00bb.
  • N:N \u2014 un \u00e9tudiant suit plusieurs modules ; on cr\u00e9e une table de jonction.
\U0001f4a1 Exemple TRIUn \u00c9tudiant s'inscrit \u00e0 plusieurs Modules (et r\u00e9ciproquement) : on cr\u00e9e une table Inscriptions (id_etudiant, id_module) \u2014 la table de jonction de la relation N:N.

2.4 Les contraintes d'int\u00e9grit\u00e9

  • NOT NULL \u2014 champ obligatoire.
  • UNIQUE \u2014 pas deux fois la m\u00eame valeur.
  • CHECK \u2014 une condition doit \u00eatre vraie (ex. prix positif).
  • FOREIGN KEY \u2026 ON DELETE CASCADE \u2014 supprimer un client supprime ses commandes.
📌 Bon à savoir
  • On analyse le besoin AVANT de créer les tables.
  • 1NF = valeurs atomiques ; la normalisation élimine les redondances.
  • Dans une relation 1:N, la clé étrangère est du côté « plusieurs ».
  • Une relation N:N se modélise avec une table de jonction.

3.1 Qu'est-ce que SQL ?

Le SQL (Structured Query Language) est le langage standard pour communiquer avec un SGBD. Il se divise en trois familles :

  • DDL (structure) : CREATE, ALTER, DROP.
  • DML (donn\u00e9es) : SELECT, INSERT, UPDATE, DELETE.
  • DCL (droits) : GRANT, REVOKE.

3.2 La requ\u00eate SELECT

ClauseR\u00f4le

FROMtable(s) source
WHEREcondition de filtrage
ORDER BYtri (ASC / DESC)
\u26a0\ufe0f Erreur graveN'oublie JAMAIS la clause WHERE dans un UPDATE ou un DELETE : sans elle, tu modifies ou supprimes toutes les lignes. Teste toujours d'abord avec un SELECT \u00e9quivalent.

Jointure (JOIN) — Croiser les données de plusieurs tables en une requête.

4.1 Les jointures

La force des BD relationnelles : croiser plusieurs tables en une requ\u00eate avec les jointures.

JointureR\u00e9sultat
INNER JOINlignes pr\u00e9sentes dans les DEUX tables
LEFT JOINtoutes les lignes de gauche (NULL si pas de correspondance)
RIGHT JOINtoutes les lignes de droite

4.2 Agr\u00e9gation et regroupement

Les fonctions d'agr\u00e9gation calculent sur un ensemble de lignes : COUNT(*) (nombre), SUM (somme), AVG (moyenne), MIN/MAX. Avec GROUP BY, on calcule par groupe ; HAVING filtre les groupes (comme WHERE, mais apr\u00e8s regroupement).

4.3 Formulaires, rapports, import/export

Pour les non-techniciens, le SGBD propose des formulaires (saisie sans \u00e9crire de SQL) et des rapports (documents imprimables). On peut aussi importer et exporter des donn\u00e9es (CSV, Excel).

\U0001f1ed\U0001f1f9 ApplicationDans une boutique \u00e0 P\u00e9tion-Ville, un formulaire Access permet \u00e0 l'employ\u00e9 de saisir les ventes sans conna\u00eetre SQL ; le soir, le g\u00e9rant g\u00e9n\u00e8re un rapport imprimable des recettes \u2014 et la base locale reste accessible m\u00eame sans Internet.
📌 Bon à savoir
  • INNER JOIN = intersection ; LEFT JOIN garde toute la table de gauche.
  • COUNT(*) compte, SUM additionne, AVG fait la moyenne.
  • GROUP BY calcule par groupe ; HAVING filtre les groupes.
  • Formulaires pour saisir, rapports pour imprimer, import/export pour échanger.

🔑 Termes clés
ALTER TABLE — Modifier la structure d'une table (ADD, MODIFY, DROP COLUMN).
Index — Structure qui accélère les recherches, comme l'index d'un livre.
GRANT — Accorder un droit à un utilisateur.
REVOKE — Retirer un droit à un utilisateur.
Sauvegarde — Copie de sécurité de la base (ex. mysqldump).
DROP TABLE — Supprimer une table entière — irréversible sans sauvegarde.

5.1 Modifier la structure (DDL)

Les besoins \u00e9voluent. Le DDL modifie la structure sans perdre les donn\u00e9es :

  • ALTER TABLE \u2026 ADD \u2014 ajouter une colonne.
  • ALTER TABLE \u2026 MODIFY \u2014 changer un type.
  • ALTER TABLE \u2026 DROP COLUMN \u2014 supprimer une colonne.
  • DROP TABLE \u2014 supprimer la table (irr\u00e9versible sans sauvegarde).

5.2 Optimiser avec les index

\u26a0\ufe0f \u00c9quilibreUn index acc\u00e9l\u00e8re les SELECT (le SGBD va droit aux lignes), mais ralentit l\u00e9g\u00e8rement les INSERT/UPDATE/DELETE (l'index doit \u00eatre mis \u00e0 jour). On indexe les colonnes souvent utilis\u00e9es dans WHERE et JOIN \u2014 pas toutes les colonnes.

5.3 S\u00e9curiser la base

La s\u00e9curit\u00e9 passe par les droits d'acc\u00e8s : GRANT accorde, REVOKE retire. Ajoute des mots de passe forts et des sauvegardes r\u00e9guli\u00e8res.

\U0001f1ed\U0001f1f9 Contexte ha\u00eftienAvec des coupures de courant fr\u00e9quentes, la sauvegarde r\u00e9guli\u00e8re est critique : sauvegardes automatiques sur cl\u00e9 USB ou disque externe, et une copie hors site. Apr\u00e8s une coupure brutale, v\u00e9rifie l'int\u00e9grit\u00e9 de la base.
📌 Bon à savoir
  • ALTER TABLE modifie la structure sans perdre les données.
  • Un index accélère les lectures mais ralentit un peu les écritures.
  • GRANT accorde un droit, REVOKE le retire.
  • Sauvegardes régulières + copie hors site : vital en contexte de coupures.

6.1 Pourquoi documenter ?

Une base non document\u00e9e est fragile : si le seul technicien qui la conna\u00eet part, personne ne peut la maintenir. Documenter est aussi une exigence professionnelle.

\u26a0\ufe0f Cas r\u00e9elDes organisations ha\u00eftiennes ont perdu des ann\u00e9es de donn\u00e9es faute de documentation et de sauvegardes accessibles. Documentation et sauvegardes hors site sont une n\u00e9cessit\u00e9 absolue.

6.2 Le dictionnaire de donn\u00e9es

Il d\u00e9crit chaque champ avec pr\u00e9cision : nom, table, type, longueur, contrainte, description. C'est la r\u00e9f\u00e9rence pour comprendre la structure.

6.3 Devis organique et manuel utilisateur

Le devis organique est le dossier technique complet : page de titre, contexte, sch\u00e9ma E/A, dictionnaire de donn\u00e9es, liste des requ\u00eates, formulaires et rapports, plan de sauvegarde, proc\u00e9dures de maintenance. Le manuel utilisateur, lui, s'adresse aux non-techniciens : simple, illustr\u00e9, sans jargon.

\U0001f4a1 Lien TRILa documentation se retrouve en TRI-15 (Assistance technique) et, en 2e ann\u00e9e, dans TRI-18 et TRI-20 (serveurs et services r\u00e9seau).
📌 Bon à savoir
  • Une base non documentée devient impossible à reprendre : documente toujours.
  • Le dictionnaire de données décrit chaque champ (type, longueur, contrainte, rôle).
  • Le devis organique = dossier technique complet ; le manuel = guide pour l'utilisateur.
  • Bonne documentation = base maintenable et pérenne.

  • Ch.1 — Notions : BD vs tableur, SGBD, table / champ / enregistrement / clé primaire.
  • Ch.2 — Concevoir : analyse, normalisation (1NF/2NF/3NF), clés étrangères, cardinalités, table de jonction.
  • Ch.3 — SQL : SELECT / INSERT / UPDATE / DELETE, WHERE, ORDER BY (DDL / DML / DCL).
  • Ch.4 — Traiter : jointures (INNER / LEFT), agrégation (COUNT/SUM/AVG) + GROUP BY, formulaires, rapports.
  • Ch.5 — Adapter & sécuriser : ALTER TABLE, index, GRANT / REVOKE, sauvegardes.
  • Ch.6 — Documenter : dictionnaire de données, devis organique, manuel utilisateur.
🧭 À connaître par cœur
  • Les 5 étapes : Analyser → Concevoir → Traiter → Adapter → Documenter.
  • Les 4 commandes DML : SELECT (lire), INSERT (ajouter), UPDATE (modifier), DELETE (supprimer) — toujours avec WHERE pour UPDATE/DELETE !
